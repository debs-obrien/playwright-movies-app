# Testing guide

This repo is a teaching project for Playwright. Start with the canonical examples, then explore feature specs grouped by list-management area.

## Where to start reading

| File | What it teaches |
|------|-----------------|
| `tests/logged-in/manage-lists-before-each.spec.ts` | Shared `beforeEach` setup with multiple tests in one file |
| `tests/logged-in/manage-lists-fixtures.spec.ts` | Custom fixtures, `test.step`, and ARIA snapshots |
| `tests/helpers/list-fixtures.ts` | Tiered list fixtures (pick the lightest seed you need) |
| `tests/logged-in/lists/*.spec.ts` | Feature-grouped specs migrated from one-test-per-file `@agent` runs |

Logged-out examples live under `tests/logged-out/`. Auth setup is in `tests/logged-in/login.setup.ts`.

## Fixture tiers

List tests share mock-api state, so `playwright.config.ts` runs with `workers: 1`. Each logged-in test resets the mock API via the `_resetMockApi` auto-fixture in `tests/helpers/base-test.ts`.

Import fixtures from `tests/helpers/list-fixtures.ts`:

```typescript
import { emptyListTest, listWithMoviesTest, listTest } from '../../helpers/list-fixtures';
```

| Fixture | Page state | Use when |
|---------|------------|----------|
| `emptyListTest` / `emptyListPage` | New list, no movies, on Add/Remove | Empty-state UI, create-then-view, choose-image-without-movies |
| `listWithMoviesTest` / `listWithMoviesPage` | List + 3 movies, no cover, on Add/Remove | Add/remove/search/cover flows that do not need View List yet |
| `listTest` / `listPage` | Full seed: 3 movies, cover image, on View List | Edit, share, my-lists, navigation, view flows |

Helpers such as `createList`, `addMovie`, and `selectCoverImage` live in `tests/helpers/list-utilities.ts`.

## Web-first assertions

Prefer role- and label-based locators over CSS classes or DOM structure:

```typescript
await expect(page.getByRole('button', { name: 'Share' })).toBeVisible();
await expect(page.getByRole('list', { name: 'movies' })).toMatchAriaSnapshot(`...`);
```

Avoid `waitForTimeout`, `force: true`, and synchronous `.count()` checks — use `expect(locator).toHaveCount(n)` instead.

## Guest / logged-out contexts

Auth tokens live in **localStorage**, not only cookies. For guest scenarios while logged-in setup exists, open a fresh context:

```typescript
const guestContext = await browser.newContext({
  storageState: { cookies: [], origins: [] },
});
const guestPage = await guestContext.newPage();
```

See `tests/logged-in/access-list-without-authentication.spec.ts` and `tests/logged-in/share-private-list.spec.ts`.

## `@agent` specs

Specs tagged `@agent` were generated by Playwright's test planner. They are consolidated under `tests/logged-in/lists/` by feature (create, edit, delete, add-movies, etc.) so each file reads like a human-written suite.

A few flows stay as standalone files when they teach a distinct pattern (multi-list delete, private share + guest context, auth gate).

## Running tests

```bash
npx playwright test --ui          # interactive
npx playwright test tests/logged-in/lists   # list feature specs only
npx playwright test --grep @agent   # agent-generated coverage only
```

CI shards the full suite across four workers per shard; local runs use one worker because the mock list store is process-global.
